## 一、结论速览

### 这个算法真正解决了什么

在移动机器人路径跟踪领域，传统方法通常面临两个核心困难：
1. **非完整约束（nonholonomic constraint）**：机器人无法原地转向，必须满足最小转弯半径；
2. **反应式路径调整**：预设路径可能被动态障碍物阻挡，需要实时避让。

该算法提出了一套**基于追踪曲线动力学的反应式路径规划器**，使机器人能够：
- 从任意初始位置和朝向**渐近收敛**到预设的贝塞尔曲线路径；
- 在收敛过程中始终满足**最小转弯半径约束**；
- 通过**动力学调制（Dynamics Modulation）** 实现对意外障碍物的反应式避让。

### 最重要的三个判断

1. **核心贡献**：将经典的追踪曲线（Pursuit Curve）概念从"追逐移动目标"重新诠释为"追逐理想化的自身状态"，并与分段贝塞尔曲线参数化路径无缝结合，形成了一个无需求解复杂最优控制问题的反应式路径跟踪框架。这不是一个纯数值优化器，而是一个具有物理解释的动力学控制器。

2. **最强证据**：项目提供了覆盖线性、二次、三次贝塞尔曲线的多场景演示（`demo_linear_bezier.cpp`、`demo_quadratic_bezier.cpp`、`demo_cubic_bezier.cpp`），以及从错误初始朝向收敛到目标路径的可视化结果（`linearbezier_demo2.gif`至`demo4.gif`），直观证明了算法的收敛性和转弯半径约束的满足。

3. **关键边界**：算法假设机器人速度恒定；避障模块基于反应式动力学调制，**不保证全局碰撞自由**；路径规划器的性能高度依赖于对"理想机器人"初始参数 $\lambda$ 的一维搜索质量，且搜索代价函数的设计缺乏理论最优性证明。

### 是否值得继续使用

- **方法学习**：值得。追踪曲线 + ICR 约束 + 贝塞尔参数化的组合提供了一个优雅的教学案例，展示了如何将经典数学概念转化为机器人控制策略。
- **实际部署**：谨慎。对于受控环境（如仓库AGV、结构化道路）可作为基线或启发式控制器；对于安全关键场景（如自动驾驶），避障模块的理论不完备性构成主要障碍。
- **复现与扩展**：推荐。代码结构清晰（`bezier_curves.hpp/cpp`、`path_planner.hpp/cpp`、`obstacles.hpp/cpp`），适合作为课程项目、研究原型或进一步理论分析的起点。

## 二、算法全景

### 研究背景与问题

移动机器人路径跟踪的经典范式包括：

- **纯追踪（Pure Pursuit）**：选择路径前方一个前瞻点作为目标，计算曲率命令；
- **Stanley 方法**：基于横向误差和航向误差计算转向角；
- **MPC（模型预测控制）**：在预测时域内求解优化问题，考虑约束。

这些方法的共同特点是：**将跟踪问题视为对几何路径的跟随**。而该算法的独特视角是：**将跟踪问题视为一个"追逐游戏"**——真实机器人（pursuer）追逐一个沿理想路径行驶的"虚拟自身"（pursuee）。这种视角转换带来了两个好处：

1. 追踪曲线的经典结论（收敛性）可以直接借用；
2. 避障时可以自然地调制"追逐方向"，而不破坏整体动力学框架。

现有工作的关键缺口：

- 纯追踪和 Stanley 方法通常不直接处理**最小转弯半径的硬约束**；
- MPC 方法计算代价高，需要求解在线优化问题；
- 反应式避障方法（如势场法、动力学调制）与非完整约束机器人的结合通常缺乏简洁的数学处理。

### 核心贡献

**作者声称的贡献**（基于 README 与代码结构）：

1. 将追踪曲线动力学嵌入路径跟踪，提供了一种具有物理直觉的收敛机制；
2. 通过 ICR 约束将最小转弯半径纳入追逐动力学；
3. 使用分段贝塞尔曲线参数化任意路径，并推导了维持恒定速度的 $\dot{\lambda}$ 公式；
4. 将路径规划问题降维为一维搜索（寻找最优初始参数 $\lambda$），使用数值梯度下降求解；
5. 集成动力学调制实现反应式避障。

**深读后能够确认的贡献**：

- 贡献 1-3 有清晰的数学推导和可视化验证，是项目最扎实的部分；
- 贡献 4 的搜索策略是启发式的，代价函数设计（距离 + 航向 + 平滑性）缺乏理论最优性分析；
- 贡献 5 被作者明确标记为"Work-in-Progress"，且作者自身质疑其在转弯半径约束下的碰撞自由保证。

### 算法地图

```text
问题：如何驱动非完整约束机器人跟踪预设路径并避障？
├── 2. Pursuit Curves：建立"追逐"动力学，证明收敛性
│   └── ICR 约束：将最小转弯半径嵌入速度向量方向限制
├── 3. Bezier Curves：参数化理想路径，推导恒定速度条件
│   └── 线性 / 二次 / 三次贝塞尔曲线的逐段组合
├── 4. Path Tracking：将跟踪问题转化为对初始参数 λ 的一维搜索
│   └── 数值梯度下降优化代价函数（距离 + 航向 + 平滑性）
├── 5. Obstacle Avoidance：动力学调制修改速度向量
│   └── 将速度分解为 v_n（朝向障碍物）和 v_e（切向）并缩放
└── 6. Demo：多场景可视化验证
```

决定算法可信度的核心部分：

- **第2节**：ICR 约束的数学正确性（简单三角学，可信）；
- **第3节**：贝塞尔曲线恒定速度推导（标准微积分，可信）；
- **第4节**：一维搜索策略的有效性和代价函数的合理性（启发式，需谨慎评估）；
- **第5节**：避障的理论保证（作者自承不完备）。

## 三、研究故事与论证链

```text
问题：给定预设路径，如何让受最小转弯半径约束的机器人从任意状态出发，
      快速收敛到路径并保持跟踪，同时能反应式避让障碍物？

→ 现有方案的不足
  - 纯几何跟踪方法（Pure Pursuit/Stanley）缺乏对非完整约束的直接处理；
  - MPC 计算代价高，实时性受限；
  - 势场法等反应式避障方法在非完整约束下易出现局部最小值或不可行速度。

→ 核心洞察
  - 追踪曲线的经典结论：追逐者总是指向被追逐者的速度向量，将从任意初始位置
    渐近收敛到被追逐者的路径；
  - 将被追逐者重新诠释为"沿理想路径行驶的虚拟机器人"，则收敛即意味着跟踪成功；
  - 通过限制追逐者速度向量的最大偏转角，可直接保证最小转弯半径约束。

→ 方法设计
  1. 用分段贝塞尔曲线定义"虚拟机器人"的理想路径；
  2. 推导虚拟机器人在贝塞尔曲线上以恒定速度行驶的参数变化率 \dot{\lambda}；
  3. 对真实机器人的每一个控制周期，通过一维搜索找到虚拟机器人的最优初始位置，
     使得追逐动力学产生的轨迹代价最小；
  4. 应用追逐动力学的第一个速度命令，重复整个过程（类 MPC 的滚动时域实现）；
  5. 遇到障碍物时，用动力学调制修改速度向量，保持速度大小不变。

→ 关键证据
  - 多场景 GIF 演示（线性/二次/三次贝塞尔，不同初始条件）；
  - 障碍物避让可视化；
  - 多机器人协调演示。

→ 结论与边界
  - 算法在演示场景中表现出良好的收敛性和路径跟踪性能；
  - 避障模块不保证碰撞自由，尤其在最小转弯半径约束下；
  - 一维搜索的代价函数和梯度下降参数影响跟踪质量，但缺乏理论指导。
```

### 论证链中的有力部分

- **追踪曲线 + ICR 约束**：这是整个算法最优雅的环节。将经典数学结论直接转化为机器人约束处理方法，无需复杂的可达性分析或最优控制。
- **贝塞尔参数化 + 恒定速度推导**：标准但必要的步骤，使得"虚拟机器人"的运动学完全确定，为后续的搜索和跟踪奠定基础。

### 可能的论证跳步

- 从"追踪曲线收敛"到"路径跟踪成功"：追踪曲线保证的是"追逐者最终到达被追逐者的路径"，但不保证"以期望的航向到达"或"在有限时间内到达"。作者通过代价函数中的"航向差异"项和"距离"项来缓解这一问题，但这增加了启发式调参的复杂度。
- 一维搜索的有效性：将路径跟踪问题简化为对单个参数 $\lambda$ 的搜索，依赖于"虚拟机器人的初始位置是唯一关键变量"的假设。这一假设在复杂路径（如自交路径、U型弯）下是否成立，未经验证。

## 四、方法、理论或解释机制

### 核心思想

该算法的核心思想可以概括为：**"追逐理想的自己"**。

传统路径跟踪是"跟随一条线"，而该算法将其转化为"追逐一个沿理想路径行驶的虚拟机器人"。这个视角转换的妙处在于：

1. **收敛性有经典理论支撑**：追踪曲线的收敛性是一个已知的数学结果；
2. **动力学自然融合**：追逐行为本身就是一种动力学过程，与机器人的运动学方程天然兼容；
3. **避障可以统一处理**：当需要避障时，只需修改"追逐方向"（速度向量），而不需要切换控制模式。

### 工作机制

#### 模块一：追踪曲线动力学 + ICR 约束

**输入**：机器人当前位姿 $(x, y, \theta)$，目标点位置 $(x_t, y_t)$，机器人速度 $v$，最小转弯半径 $R_{min}$，采样时间 $T_s$

**核心计算**：

1. 计算线段长度：$L = v \cdot T_s$
2. 计算最大允许偏转角：$\theta_{max} = \arctan\left(\frac{L}{R_{min}}\right)$
3. 计算指向目标的速度向量方向 $\phi$
4. 将 $\phi$ 限制在当前航向 $\theta$ 的 $[\theta - \theta_{max}, \theta + \theta_{max}]$ 范围内
5. 输出速度命令：$[v_x, v_y] = [v \cos\phi_{clamped}, v \sin\phi_{clamped}]$

**为什么这样设计**：

- 这是纯追踪（Pure Pursuit）的一种变体，但用"最大偏转角"显式地编码了最小转弯半径约束；
- 当 $R_{min} \to 0$（全向机器人），$\theta_{max} \to 90°$，允许瞬时任意转向；
- 当 $R_{min} \to \infty$（只能直线行驶），$\theta_{max} \to 0$，不允许任何转向。

**依赖假设**：

- 机器人速度恒定（$v$ 为常数）；
- 离散时间步长 $T_s$ 足够小，使得连续动力学近似有效；
- 机器人可以瞬时调整速度方向（即加速度方向可以突变，这在差速驱动机器人上是合理的）。

#### 模块二：贝塞尔曲线参数化与恒定速度控制

**输入**：控制点 $P_0, P_1, ..., P_n$，期望速度 $V$

**核心计算**：

对于三次贝塞尔曲线（最常用）：

$$P(\lambda) = (1-\lambda)^3 P_0 + 3(1-\lambda)^2\lambda P_1 + 3(1-\lambda)\lambda^2 P_2 + \lambda^3 P_3$$

令 $P_x = h(\lambda)$, $P_y = k(\lambda)$，则：

$$\dot{P_x} = \frac{dh}{d\lambda} \dot{\lambda}, \quad \dot{P_y} = \frac{dk}{d\lambda} \dot{\lambda}$$

要求恒定速度 $V$：

$$V^2 = \dot{P_x}^2 + \dot{P_y}^2 = \left[\left(\frac{dh}{d\lambda}\right)^2 + \left(\frac{dk}{d\lambda}\right)^2\right] \dot{\lambda}^2$$

解得：

$$\dot{\lambda} = \sqrt{\frac{V^2}{\left(\frac{dh}{d\lambda}\right)^2 + \left(\frac{dk}{d\lambda}\right)^2}}$$

**为什么这样设计**：

- 贝塞尔曲线是多项式参数曲线，计算高效，且具有凸包性质（控制点形成的多边形包含曲线）；
- 通过控制 $\dot{\lambda}$，可以精确控制虚拟机器人在曲线上的运动速度，与真实机器人的速度匹配；
- 分段组合贝塞尔曲线可以逼近任意复杂路径。

**依赖假设**：

- 曲线的切向量不为零（$\frac{dP}{d\lambda} \neq 0$），否则 $\dot{\lambda}$ 无定义；
- 控制点已预先给定（路径规划的上游问题）。

#### 模块三：路径跟踪的一维搜索

**输入**：机器人当前位姿，分段贝塞尔曲线定义的路径

**核心过程**：

1. 对每一段贝塞尔曲线，选择候选初始参数 $\lambda_0 \in [0, 1]$；
2. 将虚拟机器人放置在 $P(\lambda_0)$，并赋予航向 $\text{atan2}(\dot{P_y}, \dot{P_x})$；
3. 使用追踪曲线动力学（模块一）数值模拟机器人未来 $N$ 步的轨迹；
4. 计算轨迹代价：$J = w_1 \cdot \text{distance\_cost} + w_2 \cdot \text{heading\_cost} + w_3 \cdot \text{smoothness\_cost}$；
5. 使用数值梯度下降（或网格搜索）找到最优 $\lambda_0^*$；
6. 将模拟轨迹的第一个速度命令应用于真实机器人；
7. 下一控制周期重复步骤 1-6（滚动时域实现）。

**为什么这样设计**：

- 将原本无穷维的轨迹优化问题降维为单参数搜索，大大降低了计算复杂度；
- 滚动时域实现（类 MPC）使得算法对模型误差和扰动具有鲁棒性；
- 代价函数综合考虑了距离、航向和平滑性，试图平衡收敛速度和跟踪精度。

**依赖假设**：

- 存在一个"好的" $\lambda_0$ 使得跟踪轨迹代价最小（这一假设在简单路径下通常成立，但在复杂路径下可能不成立）；
- 数值搜索能够在实时性要求内收敛；
- 代价函数的权重 $w_1, w_2, w_3$ 已预先调好。

**如果去掉或改变**：

- 去掉搜索，固定 $\lambda_0$（如总是取 $\lambda_0 = 0$）：会导致如 README 中图"farleft"所示的灾难性180度掉头；
- 改变代价函数权重：会显著影响收敛速度和跟踪行为，但没有理论指导如何选择最优权重。

#### 模块四：动力学调制避障

**输入**：机器人当前速度 $v$，最近障碍物位置

**核心计算**：

1. 将速度分解为朝向障碍物的法向分量 $v_n$ 和切向分量 $v_e$；
2. 当接近障碍物时，按比例缩小 $v_n$（$v_n \to 0$）；
3. 调整 $v_e$ 使得 $|v|^2 = |v_n|^2 + |v_e|^2$ 保持不变；
4. 在障碍物边界处，$|v_n| = 0$，$|v_e| = |v|$（完全沿障碍物表面滑过）。

**为什么这样设计**：

- 动力学调制是一种反应式避障方法，无需预先知道障碍物形状的全局信息；
- 保持速度大小不变，意味着避障不会降低机器人的运动效率（但可能改变运动方向）。

**依赖假设**：

- 障碍物可以被局部近似为具有明确法向和切向方向的表面；
- 机器人的执行器可以实时响应调制后的速度命令。

**已知缺陷**（作者自承）：

- 动力学调制本身不保证全局碰撞自由，尤其在存在狭窄通道或多障碍物时可能陷入局部最小值；
- 当机器人有最小转弯半径约束时，即使速度向量被调制为切向，实际的轨迹可能由于转弯半径限制而与障碍物发生碰撞。

| 一维搜索可找到合适的虚拟机器人初始位置 | `middle.PNG` vs `farleft.PNG` / `farright.PNG` 对比 | 条件性支持 | 对比是定性的；缺乏代价函数 landscape 的定量分析；搜索可能收敛到局部最优 |
| 动力学调制可实现反应式避障 | `obstacle_avoidance_demo1.gif` / `demo2.gif` | 条件性支持 | 演示场景简单（单障碍物）；作者自承不保证碰撞自由 |
| 多机器人可协调跟踪各自路径 | `multi_agents_demo.gif` | 证据有限 | 仅演示两个机器人；未展示交互或冲突避免机制 |

### 实验或演示设计

项目的"实验"主要由一组 C++ 可执行文件和 Processing 可视化演示组成：

| 演示文件 | 验证目标 | 场景复杂度 |
|---|---|---|
| `demo_linear_bezier.cpp` | 线性贝塞尔（直线路径）跟踪 | 低： stair-like 折线路径 |
| `demo_quadratic_bezier.cpp` | 二次贝塞尔跟踪 | 中：平滑曲线路径 |
| `demo_cubic_bezier.cpp` | 三次贝塞尔跟踪 | 中：更复杂的曲线路径 |
| `demo_obstacles.cpp` | 避障能力 | 低：单/少量圆形障碍物 |
| `demo_multi_agents.cpp` | 多机器人协调 | 低：两个机器人，无交互 |

**评价**：

- 演示场景的设计是合理的渐进式验证（从简单到复杂）；
- 但所有场景都是**定性可视化**，缺乏定量指标（如跟踪误差 RMS、收敛时间、与障碍物的最小距离等）；
- 没有与基线方法（如 Pure Pursuit、Stanley、MPC）的定量对比。

### 最有说服力的结果

1. **从错误初始朝向的收敛**（`linearbezier_demo2.gif` - `demo4.gif`）：机器人初始位于路径之外且朝向错误，算法能够平滑地调整轨迹并收敛到目标路径。这是追踪曲线收敛性的直观验证，也是算法最突出的视觉卖点。

2. **90度转弯处的转弯半径满足**（`linearbezier_demo1.gif`）：在 stair-like 路径的直角转弯处，机器人轨迹呈现明显的圆弧过渡而非急转，表明 ICR 约束在起作用。

3. **虚拟机器人初始位置的影响**（`farleft.PNG` / `farright.PNG` / `middle.PNG`）：这组对比图清晰地说明了一维搜索的必要性——不同的初始 $\lambda$ 导致截然不同的跟踪行为。

### 反直觉结果与失效条件

1. **固定 $\lambda_0$ 的灾难性后果**：README 中展示的"farleft"情况（虚拟机器人从极左侧出发）导致真实机器人先向错误方向行驶，再急转180度。这说明算法的成功**高度依赖搜索模块**；如果搜索失败，跟踪性能可能极差。

2. **避障与转弯半径的潜在冲突**：作者在第7节明确承认，动力学调制可能无法在有最小转弯半径约束时保证碰撞自由。这是一个根本性的理论缺口，意味着在狭窄空间或障碍物密集环境中，算法可能失效。

3. **缺乏定量鲁棒性分析**：README 和演示中未展示算法对以下因素的敏感度：
   - 采样时间 $T_s$ 的变化；
   - 速度 $v$ 的变化；
   - 代价函数权重 $w_1, w_2, w_3$ 的变化；
   - 障碍物形状（非圆形、凹形障碍物）的影响。

## 六、可信度、局限与复现边界

### 证据最扎实的部分

1. **ICR 约束的数学推导**：基于简单的几何关系（弧长 = 半径 × 角度），将最小转弯半径转化为最大偏转角限制。推导简洁、正确、可验证。

2. **贝塞尔曲线恒定速度控制**：通过对参数曲线求导和链式法则，得到 $\dot{\lambda}$ 的显式表达式。这是标准微积分，无误。

3. **追踪曲线的收敛性**：虽然项目未给出形式化证明，但追踪曲线的收敛性是经典数学结果（可追溯到19世纪），在大量文献中有记载。

### 会影响解释的关键问题

1. **一维搜索的优化 landscape**：将路径跟踪问题降维为单参数搜索是一个大胆的简化。对于复杂路径（如自交、紧密弯道、长路径），代价函数 $J(\lambda)$ 可能有多个局部最小值，梯度下降可能收敛到次优解。项目未分析代价函数的凸性或 landscape 特征。

2. **滚动时域的稳定性**：算法采用类 MPC 的滚动时域实现，但缺乏稳定性证明。在 MPC 中，稳定性通常需要通过终端代价或终端约束来保证；该项目未讨论这些理论问题。

3. **避障的理论缺口**：动力学调制是一种反应式方法，已知存在局部最小值问题（如机器人在两个障碍物之间震荡）。作者正确地指出了这一问题，但未提出解决方案。

4. **参数调谐的黑箱性**：代价函数权重 $w_1, w_2, w_3$ 和梯度下降的步长、迭代次数等超参数对性能有显著影响，但缺乏调参指导。

### 局限性

**作者明确承认的局限**（README 第7节）：
>I am working on incorporating obstacle avoidance into the planner using dynamics modulation. However, since a robot might has a minimum turning radius constraint, I concern that dynamics modulation might not guarantee a collision-free path. Therefore, more investigations are needed."
> 即：避障模块在有转弯半径约束时不保证碰撞自由，需要进一步研究。

**基于项目证据进一步推断的局限**：

- 所有演示均基于恒定速度假设，未验证变速场景；
- 未与任何基线方法进行定量比较，无法判断性能优势；
- 演示场景相对简单，未测试高曲率路径、动态障碍物、传感器噪声等真实世界因素；
- 多机器人演示未展示机器人之间的交互或冲突避免机制，仅展示各自独立跟踪。

**当前无法确认**：

- 数值搜索的计算时间是否满足实时性要求（取决于实现细节和硬件平台）；
- 算法在真实机器人（而非仿真）上的性能表现；
- 动力学调制模块的具体实现细节（与外部仓库的集成方式）。

### 复现与落地风险

**需要的材料**：

- 代码：项目已提供完整的 C++ 源码和 CMake 构建配置；
- 可视化：Processing 仿真环境（`.pde` 文件）和配置文件（`.txt`）；
- 依赖：标准 C++ 库、CMake、Processing 环境。

**缺失细节**：

- 代价函数的具体权重值；
- 数值梯度下降的步长和迭代次数；
- 仿真的时间步长 $T_s$ 和机器人速度 $v$ 的具体数值；
- 障碍物检测和距离计算的具体实现（在 `obstacles.cpp` 中，但 README 未详述）。

**第一批验证动作**：

1. 构建项目并运行 `demo_linear_bezier`，验证基本跟踪功能；
2. 修改初始位姿（特别是极端错误的朝向），观察收敛行为；
3. 打印并分析代价函数 $J(\lambda)$ 的 landscape，验证一维搜索的合理性；
4. 在避障场景中故意设置狭窄通道，测试碰撞自由保证是否成立。

**最可能失败的位置**：

- 一维搜索收敛到局部最优，导致跟踪轨迹震荡或收敛缓慢；
- 避障场景中，机器人在障碍物附近由于转弯半径限制无法及时转向，发生碰撞。

## 七、可复用洞察与研究行动

### 值得复用

1. **"追踪曲线 + ICR 约束"框架**：这是一个优雅且计算高效的方法，将最小转弯半径约束直接嵌入速度向量选择。可以迁移到任何需要满足非完整约束的跟踪或追逐问题。

2. **贝塞尔曲线恒定速度参数化**：$\dot{\lambda}$ 的显式公式是一个有用的工具，不仅用于本项目，也可用于任何需要沿参数曲线以恒定速度运动的应用（如动画、数控加工、无人机轨迹规划）。

3. **一维搜索降维思想**：虽然搜索策略本身是启发式的，但"将高维轨迹优化降维为少量关键参数搜索"的思想具有普遍价值。在实时性要求严格的场景中，这种降维是必要的妥协。

4. **类 MPC 的滚动时域实现**：通过在每个控制周期重新规划，算法天然具有对扰动和模型误差的鲁棒性。这种实现范式可以迁移到其他规划问题。

### 不应直接照搬

1. **代价函数设计和权重选择**：当前的代价函数（距离 + 航向 + 平滑性）及其权重是启发式的，缺乏理论最优性。在不同机器人平台、不同路径类型或不同任务目标下，需要重新调参或重新设计。

2. **动力学调制避障模块**：由于不保证碰撞自由，不应直接用于安全关键场景。需要替换为具有理论保证的避障方法（如基于可达性分析的方法、或结合全局规划的局部避障方法）。

3. **恒定速度假设**：实际机器人通常需要变速（如减速通过弯道、加速通过直道）。直接应用本项目需要扩展为变速场景。

4. **纯数值搜索的实现**：当前使用数值梯度下降，可能不是最高效或最鲁棒的搜索策略。对于更复杂的路径，可能需要更聪明的初始化策略或多分辨率搜索。

### 与用户课题的连接

本项目适合以下类型的研究者或任务：

- **移动机器人路径跟踪的教学与入门**：算法直觉清晰，数学推导简洁，代码结构良好；
- **反应式规划的原型开发**：可作为快速原型，验证"追踪曲线 + 参数化路径"的基本可行性；
- **非完整约束控制的研究**：ICR 约束的处理方法可以作为更复杂控制器的组件；
- **多机器人协调的启发式基线**：虽然当前多机器人演示简单，但框架可以扩展为更复杂的协调策略。

### 下一步研究问题

1. **理论问题**：能否为一维搜索的代价函数设计提供理论指导？例如，是否存在一个最优性准则（如最小时间、最小能量），使得该搜索策略成为某个优化问题的精确解或近似解？

2. **稳定性问题**：滚动时域实现的渐近稳定性是否可以通过终端代价或终端约束来证明？

3. **避障保证**：如何修改动力学调制（或替换为其他方法），使其在非完整约束下也能保证碰撞自由？是否可以结合 ICR 约束进行"可达性分析"，预先排除会导致碰撞的速度命令？

4. **变速扩展**：如何将恒定速度假设放松为变速场景？这是否会显著增加问题的复杂度？

5. **复杂路径验证**：算法在自交路径、紧密弯道、长距离路径上的性能如何？代价函数的 landscape 在这些场景下有何特征？

   - 构建并运行项目演示，直观理解算法行为；

   - 分析代价函数 $J(\lambda)$ 的 landscape，验证一维搜索的合理性；
   - 将避障模块替换为具有理论保证的方法（如 NMPC、人工势场 + 局部最小值逃逸），并比较性能。

3. **条件成熟后**：
   - 在真实机器人平台上部署和验证；
   - 将算法扩展为变速、动态障碍物、多机协调等更复杂的场景；
   - 撰写技术报告或论文，填补当前的理论缺口（如稳定性证明、避障保证）。
