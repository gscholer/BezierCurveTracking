# 模块四：动力学调制避障 — 实现细节

> 本文档基于 `include/bezier_tracking/obstacles.hpp`、`src/obstacles.cpp` 和 `src/path_planner.cpp` 的源代码，对算法核心模块四的实现进行逐层拆解。模块四负责：**当机器人接近障碍物时，通过动力学调制修改其速度向量，使机器人在保持速度大小的同时，沿障碍物表面滑过**。

---

## 一、模块概述

模块四是一个**反应式避障层**，它被集成在路径跟踪框架中，但设计上保持相对独立。当机器人检测到障碍物时，模块四介入并修改由模块一/二/三计算出的速度命令；当机器人远离障碍物时，模块四不产生影响。

### 核心设计思想

动力学调制（Dynamics Modulation）的核心直觉是：
- 将机器人速度分解为**朝向障碍物的法向分量** $v_n$ 和**沿障碍物表面的切向分量** $v_e$；
- 当接近障碍物时，**缩小法向分量**（$v_n \to 0$），使机器人不再朝向障碍物运动；
- **放大切向分量**，使总速度大小 $|v|$ 保持不变；
- 在障碍物边界处，法向分量完全归零，机器人完全沿表面滑过。

### 输入输出

| 输入项 | 说明 |
|---|---|
| `x0, y0` | 机器人当前位置 |
| `theta0` | 机器人当前航向 |
| `vx, vy`（引用传递） | 模块一/三计算出的原始速度命令（输入并被修改） |
| `params_.obstacles` | 障碍物列表 |

| 输出项 | 说明 |
|---|---|
| `vx, vy`（修改后） | 经动力学调制和 ICR 约束后的最终速度命令 |

## 二、障碍物类体系

### 2.1 Obstacle 抽象基类（obstacles.hpp:6-15）

```cpp
class Obstacle{
    public:
        virtual float evaluate(float x, float y) = 0;
        virtual void gradient(float x, float y, float &gx, float &gy) = 0;
        virtual std::vector<float> properties() = 0;
        virtual std::string shape() = 0;
        bool is_collided(float x, float y);
};
```

| 纯虚函数 | 数学意义 |
|---|---|
| `evaluate(x, y)` | 位置 $(x, y)$ 到障碍物的**归一化距离度量**；$eval = 1$ 表示在边界上，$eval < 1$ 表示在内部，$eval > 1$ 表示在外部 |
| `gradient(x, y)` | 障碍物在 $(x, y)$ 处的**法向单位向量**（指向外部） |
| `is_collided(x, y)` | 判断点是否在障碍物内部或边界上（`evaluate <= 1`） |

### 2.2 Circle 派生类（obstacles.hpp:17-38, obstacles.cpp:12-52）

当前项目只实现了**圆形障碍物**，但基类设计为扩展其他形状（如椭圆、多边形）预留了接口。

**evaluate 实现**：
```cpp
float Circle::evaluate(float x, float y){
    return (std::pow(x-params_.xc, 2) + std::pow(y-params_.yc, 2)) / std::pow(params_.r, 2);
}
```

这是**归一化欧氏距离平方**：
$$eval(x, y) = \frac{(x - x_c)^2 + (y - y_c)^2}{r^2}$$

| 位置 | $eval$ 值 | 物理意义 |
|---|---|---|
| 障碍物中心 | $0$ | 内部 |
| 边界上 | $1$ | 碰撞临界 |
| 外部 | $> 1$ | 安全区域 |
| 距离中心 $2r$ | $4$ | 较远 |

**gradient 实现**：
```cpp
void Circle::gradient(float x, float y, float &gx, float &gy){
    gx = x - params_.xc;
    gy = y - params_.yc;
    float mag = std::sqrt(std::pow(gx, 2) + std::pow(gy, 2));
    gx = gx / mag;
    gy = gy / mag;
}
```

返回从圆心指向 $(x, y)$ 的**单位向量**：
$$\vec{n} = \frac{(x - x_c, y - y_c)}{\sqrt{(x - x_c)^2 + (y - y_c)^2}}$$

这是障碍物表面的**外法向**（对于圆形，径向朝外）。

## 三、核心函数：obstacle_avoidance 逐行解析

### 3.1 函数签名与变量声明

```cpp
void PathPlanner::obstacle_avoidance(
    float x0, float y0, float theta0, float &vx, float &vy
)
```

**关键设计**：`vx, vy` 以**引用传递**，意味着函数直接修改输入的速度命令。

**局部变量**：

| 变量 | 含义 |
|---|---|
| `nx, ny` | 障碍物法向单位向量 |
| `ex, ey` | 障碍物切向单位向量（法向逆时针旋转 90°） |
| `det` | 基变换矩阵的行列式 |
| `v_perp, v_away` | 速度在法向和切向的分量 |
| `vx_list, vy_list` | 每个障碍物调制后的速度候选 |
| `eval_list` | 每个障碍物的 evaluate 值 |
| `w` | 多障碍物加权系数 |

### 3.2 主循环：逐障碍物处理

```cpp
for (auto obstacle : params_.obstacles){
    // 碰撞检测
    if (obstacle->evaluate(x0, y0) < 1){
        std::cout << "collision!!!\n";
    }

    eval_list.push_back(obstacle->evaluate(x0, y0));

    // 获取法向
    obstacle->gradient(x0, y0, nx, ny);

    // 构造切向（法向逆时针旋转 90°）
    ex = ny;
    ey = -nx;

    // 速度分解到 (法向, 切向) 基
    det = nx*ey - ex*ny;
    v_perp = (ey/det)*vx - (ex/det)*vy;
    v_away = -(ny/det)*vx + (nx/det)*vy;
```

#### 步骤 1：碰撞检测

```cpp
if (obstacle->evaluate(x0, y0) < 1){
    std::cout << "collision!!!\n";
}
```

注意使用的是 `< 1` 而非 `<= 1`，这意味着**恰好在边界上不算碰撞**。这是一个细微的设计选择——边界上的机器人被视为"刚好接触"而非"已经碰撞"。

#### 步骤 2：构造法向-切向坐标系

```cpp
obstacle->gradient(x0, y0, nx, ny);  // 法向单位向量
ex = ny;
ey = -nx;                            // 切向单位向量
```

切向通过将法向**逆时针旋转 90°** 得到：
$$\vec{e} = R_{90°} \vec{n} = \begin{bmatrix} 0 & -1 \\ 1 & 0 \end{bmatrix} \begin{bmatrix} n_x \\ n_y \end{bmatrix} = \begin{bmatrix} -n_y \\ n_x \end{bmatrix}$$

等等，代码中是 `ex = ny, ey = -nx`，即 $\vec{e} = (n_y, -n_x)$。这是**顺时针旋转 90°**！

实际上，两种旋转方向都是合法的切向，只是定义了不同的方向 convention。重要的是 $\vec{n}$ 和 $\vec{e}$ 构成正交基：
$$\vec{n} \cdot \vec{e} = n_x n_y + n_y (-n_x) = 0\ ✓$$

#### 步骤 3：速度分解

```cpp
det = nx*ey - ex*ny;  // = nx*(-nx) - ny*ny = -(nx² + ny²) = -1

v_perp = (ey/det)*vx - (ex/det)*vy;
v_away = -(ny/det)*vx + (nx/det)*vy;
```

**数学推导**：

我们希望将速度 $\vec{v} = (v_x, v_y)$ 分解到正交基 $(\vec{n}, \vec{e})$ 上：
$$\vec{v} = v_\perp \vec{n} + v_\text{away} \vec{e}$$

即：
$$\begin{bmatrix} v_x \\ v_y \end{bmatrix} = \begin{bmatrix} n_x & e_x \\ n_y & e_y \end{bmatrix} \begin{bmatrix} v_\perp \\ v_\text{away} \end{bmatrix}$$

代入 $e_x = n_y$, $e_y = -n_x$：
$$\begin{bmatrix} v_x \\ v_y \end{bmatrix} = \begin{bmatrix} n_x & n_y \\ n_y & -n_x \end{bmatrix} \begin{bmatrix} v_\perp \\ v_\text{away} \end{bmatrix}$$

行列式：

$$det = n_x(-n_x) - n_y(n_y) = -(n_x^2 + n_y^2) = -1$$

逆矩阵：

$$\begin{bmatrix} v_\perp \\ v_\text{away} \end{bmatrix} = \frac{1}{-1} \begin{bmatrix} -n_x & -n_y \\ -n_y & n_x \end{bmatrix} \begin{bmatrix} v_x \\ v_y \end{bmatrix} = \begin{bmatrix} n_x & n_y \\ n_y & -n_x \end{bmatrix} \begin{bmatrix} v_x \\ v_y \end{bmatrix}$$

展开：

$$v_\perp = n_x v_x + n_y v_y = \vec{n} \cdot \vec{v}$$
$$v_\text{away} = n_y v_x - n_x v_y = \vec{e} \cdot \vec{v}$$

验证代码：

- $v_\perp = (e_y/det) v_x - (e_x/det) v_y = (-n_x / -1) v_x - (n_y / -1) v_y = n_x v_x + n_y v_y$ ✓
- $v_\text{away} = -(n_y/det) v_x + (n_x/det) v_y = -(n_y / -1) v_x + (n_x / -1) v_y = n_y v_x - n_x v_y$ ✓

**结论**：

- $v_\perp$ 是速度在**法向**的投影（正值表示远离障碍物，负值表示朝向障碍物）；
- $v_\text{away}$ 是速度在**切向**的投影。

### 3.3 动力学调制（核心）

```cpp
// 调制条件：速度朝向障碍物，或已经在障碍物内部/边界
if (nx*vx + ny*vy < 0 || obstacle->evaluate(x0,y0) <= 1){
    // 缩小法向分量
    v_perp = v_perp * (1 - 1/std::pow(obstacle->evaluate(x0,y0), 1/params_.reactivity));
    v_perp = std::min(std::max(v_perp, -params_.vel), params_.vel);

    // 调整切向分量，保持速度大小
    if (v_away >= 0){
        v_away = std::sqrt(std::pow(params_.vel, 2) - std::pow(v_perp, 2));
    }
    else{
        v_away = -std::sqrt(std::pow(params_.vel, 2) - std::pow(v_perp, 2));
    }
}

// 将调制后的速度转换回笛卡尔坐标
vx_list.push_back(nx*v_perp + ex*v_away);
vy_list.push_back(ny*v_perp + ey*v_away);
```

#### 调制条件

```cpp
if (nx*vx + ny*vy < 0 || obstacle->evaluate(x0,y0) <= 1)
```

| 条件 | 含义 |
|---|---|
| `nx*vx + ny*vy < 0` | 速度法向投影为负，即机器人**朝向**障碍物运动 |
| `evaluate <= 1` | 机器人已经在障碍物**内部或边界上** |

**逻辑**：只有当机器人朝向障碍物运动时，或者已经接触到障碍物时，才需要进行调制。如果机器人正在远离障碍物，即使距离很近，也不调制。

#### 法向分量调制

```cpp
v_perp = v_perp * (1 - 1/std::pow(obstacle->evaluate(x0,y0), 1/params_.reactivity));
```

令 $\alpha = params_.reactivity$（反应性系数），$eval = obstacle->evaluate(x0, y0)$。

调制公式：

$$v_\perp^{new} = v_\perp \cdot \left(1 - \frac{1}{eval^{1/\alpha}}\right)$$

**分析不同距离下的行为**：

| $eval$ | $eval^{1/\alpha}$ | $1/eval^{1/\alpha}$ | $v_\perp^{new}$ | 效果 |
|---|---|---|---|---|
| $1$（边界） | $1$ | $1$ | $0$ | 法向完全消除 |
| $2$ | $2^{1/\alpha}$ | $1/2^{1/\alpha}$ | $v_\perp(1 - 1/2^{1/\alpha})$ | 部分抑制 |
| $\to \infty$ | $\to \infty$ | $\to 0$ | $\to v_\perp$ | 无影响 |

**反应性系数 $\alpha$ 的影响**：

| $\alpha$ | 调制特征 |
|---|---|
| 小（如 0.5）| $eval^{1/\alpha}$ 增长极快，调制在远距离就开始生效，反应"过度敏感" |
| 大（如 2.0）| $eval^{1/\alpha}$ 增长缓慢，仅在极近距离才调制，反应"迟钝" |
| $= 1$ | 线性衰减，$v_\perp^{new} = v_\perp(1 - 1/eval)$ |

默认值为 1（在 `PathPlanner::Params` 中 `float reactivity = 1`）。

**钳制处理**：
```cpp
v_perp = std::min(std::max(v_perp, -params_.vel), params_.vel);
```

防止数值误差导致 $v_\perp$ 超出 $[-V, V]$ 范围。

#### 切向分量调整

```cpp
if (v_away >= 0){
    v_away = std::sqrt(std::pow(params_.vel, 2) - std::pow(v_perp, 2));
}
else{
    v_away = -std::sqrt(std::pow(params_.vel, 2) - std::pow(v_perp, 2));
}
```

**核心约束**：保持速度大小不变 $|\vec{v}| = V$。

由于 $\vec{n}$ 和 $\vec{e}$ 是正交单位向量：

$$|\vec{v}|^2 = v_\perp^2 + v_\text{away}^2 = V^2$$

解得：

$$v_\text{away} = \pm \sqrt{V^2 - v_\perp^2}$$

代码保持切向分量的**符号不变**（`v_away >= 0` 时取正，否则取负），确保机器人沿相同方向"滑过"障碍物。

#### 转换回笛卡尔坐标

```cpp
vx_list.push_back(nx*v_perp + ex*v_away);
vy_list.push_back(ny*v_perp + ey*v_away);
```

逆变换：
$$\vec{v}^{new} = v_\perp^{new} \vec{n} + v_\text{away}^{new} \vec{e}$$

### 3.4 多障碍物加权平均

```cpp
// 计算权重
std::vector<float> w;
w.resize(params_.obstacles.size());
float w_total = 0;

for (int i = 0; i < params_.obstacles.size(); i++){
    w[i] = 1;
    for (int j = 0; j < params_.obstacles.size(); j++){
        if (j != i){
            w[i] *= (eval_list[j] - 1);
        }
    }
    w_total += w[i];
}

// 加权平均
vx = 0;
vy = 0;
for(int k = 0; k < params_.obstacles.size(); k++){
    vx += (w[k]/w_total)*vx_list[k];
    vy += (w[k]/w_total)*vy_list[k];
}
```

**权重设计分析**：

权重公式：

$$w_i = \prod_{j \neq i} (eval_j - 1)$$

**行为分析**：

| 场景 | 权重分布 | 结果 |
|---|---|---|
| 机器人接近障碍物 $k$（$eval_k \approx 1$）| $w_k \approx \prod_{j \neq k}(eval_j - 1)$，其他 $w_i \approx 0$ | **障碍物 $k$ 的调制结果主导** |
| 机器人远离所有障碍物（所有 $eval_j \gg 1$）| 所有权重相近 | 近似平均所有调制结果 |
| 机器人同时接近两个障碍物 | 两个障碍物的权重都较大 | 混合两种调制效果 |

**设计意图**：

- 当机器人接近某个障碍物时，该障碍物的影响被放大；
- 当机器人远离障碍物时，所有障碍物的影响均匀混合；
- 这种设计避免了简单平均导致的"远距离障碍物过度影响"问题。

**注意**：如果机器人恰好在某个障碍物内部（$eval_k = 0$），则 $w_i$（$i \neq k$）中包含因子 $(0 - 1) = -1$，可能导致权重为负。这是该权重方案的一个**理论缺陷**。

### 3.5 ICR 约束的再次应用

```cpp
// 重新应用最小转弯半径约束
rotate(heading_x, heading_y, theta0);
theta_diff = find_angle(vx, vy, heading_x, heading_y);
if(std::abs(theta_diff) > theta_diff_max){
    if(theta_diff <= 0){
        rotate(vx, vy, theta_diff + theta_diff_max);
    }
    else{
        rotate(vx, vy, theta_diff - theta_diff_max);
    }
}
```

这是模块一 ICR 约束的**完全复用**。避障后的速度方向可能超出机器人的最大转向能力，因此需要再次钳制。

**注意**：这与作者在第 7 节（Work-in-Progress）中表达的担忧直接相关——即使速度向量被调制为切向，ICR 约束可能导致实际轨迹偏离调制方向，从而**无法保证碰撞自由**。

## 四、完整控制流程图

```
输入: (x0, y0, θ0, vx, vy)  ← 原始速度命令
│
├─► 对每个障碍物:
│   │
│   ├─► 碰撞检测: eval < 1 ?
│   │
│   ├─► 获取法向 n = gradient(x0, y0)
│   ├─► 构造切向 e = (ny, -nx)
│   │
│   ├─► 速度分解: [v_perp, v_away] = [n·v, e·v]
│   │
│   ├─► 【动力学调制】
│   │   ├─► 条件: n·v < 0 (朝向障碍物) 或 eval <= 1 (在内部)
│   │   ├─► 缩小法向: v_perp *= (1 - 1/eval^(1/α))
│   │   ├─► 钳制: v_perp = clamp(v_perp, -V, V)
│   │   └─► 调整切向: v_away = sign(v_away) * sqrt(V² - v_perp²)
│   │
│   └─► 转换回笛卡尔: v_i = v_perp*n + v_away*e
│
├─► 多障碍物加权平均
│   └─► w_i = ∏(eval_j - 1),  v_final = Σ(w_i/w_total)*v_i
│
├─► 【ICR 约束】将 v_final 旋转至允许航向范围内
│
└─► 输出: (vx, vy)  ← 最终速度命令
```

## 六、关键设计决策与潜在问题

### 6.1 设计决策分析

**决策 1：反应式触发条件（仅当朝向障碍物时才调制）**

```cpp
if (nx*vx + ny*vy < 0 || obstacle->evaluate(x0,y0) <= 1)
```

这是一个重要的效率优化：如果机器人正在远离障碍物，即使距离很近，也不需要进行调制。这避免了不必要的速度扰动。

**潜在问题**：如果机器人与障碍物相切运动（$\vec{n} \cdot \vec{v} \approx 0$），但轨迹由于动力学扰动可能在未来朝向障碍物，反应式设计不会提前规避。

**决策 2：保持切向分量符号**

```cpp
if (v_away >= 0) { v_away = +sqrt(...) } else { v_away = -sqrt(...) }
```

这意味着机器人始终沿**相同方向**滑过障碍物（不会突然反向）。这确保了轨迹的连续性，但可能导致机器人在某些几何构型下选择次优的绕行方向。

**决策 3：多障碍物的乘积权重**

$$w_i = \prod_{j \neq i} (eval_j - 1)$$

这种权重设计在机器人接近某个障碍物时自动放大该障碍物的影响，但：
- 计算复杂度为 $O(N^2)$（$N$ 为障碍物数量）；
- 当 $eval_j < 1$（在某个障碍物内部）时，权重可能为负，导致数值异常。

### 6.2 作者自承的局限

README 第 7 节明确指出：

> "I am working on incorporating obstacle avoidance into the planner using dynamics modulation. However, since a robot might has a minimum turning radius constraint, I concern that dynamics modulation might not guarantee a collision-free path. Therefore, more investigations are needed."

**代码层面的体现**：

1. **ICR 约束在避障后应用**：`obstacle_avoidance()` 的最后一步将调制后的速度方向钳制在 `theta_diff_max` 范围内。这意味着：
   - 理想情况下，避障速度应完全沿障碍物切向；
   - 但 ICR 约束可能要求速度方向偏离切向；
   - 偏离后的轨迹可能重新朝向障碍物，导致碰撞。

2. **无轨迹预测**：避障仅基于当前位置的速度调制，不预测未来轨迹。如果调制后的速度在下一步导致机器人进入障碍物，`obstacle_avoidance()` 在下一步会再次调制，但这是一个**反应式循环**，而非**预防式规划**。

3. **碰撞检测仅为日志输出**：
   ```cpp
   if (obstacle->evaluate(x0,y0) < 1){
       std::cout << "collision!!!\n";
   }
   ```
   代码检测到碰撞后仅打印日志，**不触发任何应急行为**（如紧急制动、路径重规划）。

### 6.3 其他潜在问题

| 问题 | 触发条件 | 影响 |
|---|---|---|
| 权重为负 | 机器人在某障碍物内部（$eval < 1$）且存在其他障碍物 | 加权平均结果不合理 |
| $V^2 - v_\perp^2 < 0$ | 数值误差导致 $v_\perp > V$ | `sqrt` 输入为负，产生 NaN |
| 局部最小值 | 两个障碍物之间 | 机器人在两障碍物间震荡，无法逃逸 |
| 切向选择次优 | 障碍物几何复杂 | 机器人沿"错误"方向绕行，路径过长 |

## 七、与模块一/二/三的交互

### 7.1 调用时机

在 `demo_obstacles.cpp`（虽然未直接阅读，但可以推断）中，避障函数的调用顺序为：

```cpp
// 1. 获取追踪速度（模块一/三）
trajectory = planner.tracking(x_current, y_current, theta_current);
vx = trajectory.vel[0][0];
vy = trajectory.vel[0][1];

// 2. 应用避障调制（模块四）
planner.obstacle_avoidance(x_current, y_current, theta_current, vx, vy);

// 3. 使用调制后的速度更新状态
x_next = x_current + vx * dt;
y_next = y_current + vy * dt;
```

### 7.2 交互接口

模块四与模块一/三的关系是**串联的**：
- 模块一/三负责"去哪里"（路径跟踪）；
- 模块四负责"不要撞到什么"（避障修正）。

这种设计意味着：
- 避障优先于路径跟踪（模块四直接修改模块一/三的输出）；
- 但避障不重新规划路径（没有回到模块二/三进行重搜索）。

## 八、小结

模块四是一个**简洁但理论上不完备**的反应式避障层：

1. **动力学调制的数学实现是优雅的**：通过正交分解、法向抑制、切向补偿，在保持速度大小的同时实现避障，物理直觉清晰；
2. **多障碍物加权机制是务实的**：乘积权重自动突出最近障碍物的影响，避免了远距离干扰；
3. **与 ICR 约束的冲突是根本性的**：这是作者明确承认的局限，也是该模块最大的理论缺口。

**最值得关注的技术细节**：

- 调制公式中的 `1/params_.reactivity` 是一个容易混淆的写法——它实际上是 $eval^{(1/\alpha)}$ 而非 $(eval^{1})^{/\alpha}$；
- 碰撞检测 `< 1` 与 `is_collided()` 中的 `<= 1` 存在不一致，边界情况的处理存在歧义；
- 避障后的 ICR 约束应用是"事后补救"，无法从根本上保证碰撞自由。

**使用建议**：

- 对于**单障碍物、开阔空间**的场景，模块四表现良好；
- 对于**多障碍物密集环境、狭窄通道**的场景，需要替换为具有理论保证的避障方法（如基于可达性分析的 NMPC、或结合全局路径规划的局部避障）。
